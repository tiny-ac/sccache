# REAPI (experimental)

sccache built with the `reapi` feature can use a REAPI v2.1 server for Rust compiles, set in `[dist.reapi]` (see [Configuration](Configuration.md)).

sccache connects to the server and hashes each toolchain's files once while it runs. The digests are kept in `<dist cache_dir>/reapi-digests.json`, so after a restart only changed files are hashed again. A Rust compile that misses sccache's cache is looked up in the server's action cache. On a hit, sccache writes its outputs and caches them as it would a local compile's. The server doesn't run compiles: a miss runs locally with the arguments a REAPI worker uses, with a copy of the Rust sysroot under `<dist cache_dir>/reapi-sysroot-copies`, which is never removed. `SCCACHE_RECACHE` and `SCCACHE_NO_CACHE` skip the lookup. Each action carries the `salt` and the `platform` properties of `[dist.reapi]`, so clients with a different salt or platform don't share action cache entries. `sccache --show-stats` counts the action cache hits, and lists, by reason, the compiles that ran locally.

A failed connection is retried after 5 to 60 seconds, and a failed hashing of a toolchain after a minute. After 3 action cache lookups fail in a row, compiles skip the lookup for 5 seconds, doubling up to 60 while lookups keep failing. A server older than REAPI v2.1, or a server that refuses the token, isn't used until sccache restarts. A toolchain without rustc or std isn't used until it changes. A rustc whose `rustc -vV` prints `commit-hash: unknown` always compiles locally.
